# 03 — The IR

**One intermediate representation crosses every stage: an indexed triangle `Mesh`.** Primitives emit it, kinds compose it, QA, the rasteriser and the GLB writer consume it. Nothing else crosses a module boundary. Source: `src/core/mesh.ts`, `src/core/asset.ts`.

## Conventions

| Convention | Value | Why |
|---|---|---|
| Units | Metres | Real dimensions from reference sheets drop straight in ([ADR 004](../decisions/004-z-up-metres.md)) |
| Up | +Z | Architecture, vehicles and CAD think in plan (XY) + height |
| Front | +X | One rule for every asset; the leading end of a loco, the gun of a tank |
| Left / right | +Y / −Y | Follows from Z-up, X-front, right-handed |
| Ground | z = 0 | Primitives put their base at `at`; things stand on the ground |
| glTF output | Y-up, front +Z | Root rotation `[-0.5, -0.5, -0.5, 0.5]`: authoring +X front → glTF +Z, +Z up → +Y, +Y left → +X ([ADR 009](../decisions/009-gltf-front-axis.md)). Part numbers stay Z-up and readable |
| Rotation | Parts: yaw about local Z. Meshes: any rotation via `place` / `applyAffine` | Part yaw covers turrets, doors, street layout; mesh-level `place` covers sloped plates, angled rods |
| Colour | Linear RGB per vertex | glTF `COLOR_0` space; `hex()` converts from sRGB |

## `Mesh`

| Field | Type | Per |
|---|---|---|
| `positions` | `Float32Array` | vertex × 3 |
| `normals` | `Float32Array` | vertex × 3 |
| `uvs` | `Float32Array` | vertex × 2, into the shared trim sheet ([04](04-materials.md)) |
| `colors` | `Float32Array` | vertex × 3, linear RGB |
| `indices` | `Uint32Array` | triangle × 3, counter-clockwise from outside |

Helpers: `MeshBuilder` (`vertex`, `tri`, `quad`, `build`), `merge`, `translate`, `boundsOf`, `triangleCount`. Transforms (`src/core/transform.ts`): `place(mesh, { at, yaw, pitch, roll, scale })`, `affine`, `frame`, `applyAffine`. Rotation order Z (yaw) · Y (pitch) · X (roll); normals are rotated and renormalised, so use uniform scale.

## Parts

A compiled asset is a flat, ordered list of parts; the hierarchy is in `parent` pointers.

| Field | Meaning |
|---|---|
| `name` | Unique, snake_case. A pivot's name becomes its glTF node and mesh name; static parts merge into their pivot on export ([batching](#batching-parts--pivots)) |
| `mesh` | `Mesh` or `null` (a group / pivot) |
| `at` | Translation in the parent's space = the pivot |
| `parent` | Part name or `null` (child of the root node) |
| `yaw` | Rotation about local Z |
| `motion` | `spin` / `slide` / `sway` / `null`; baked to a looping clip named `run` only with `animations: true` |
| `emitter` | Particle source config, exported as `extras.ts23d.emitter` on an empty node |
| `socket` | Attachment point config, exported as `extras.ts23d.socket` on an empty node |
| `surface` | `opaque` · `cutout` · `glass` · `translucent`; picks one of ≤ 4 shared materials |

**Pivots go where the part hinges.** A turret group sits on the ring; the gun group sits at the trunnion; the barrel is offset forward from it. Rotate `gun` in the engine and the barrel elevates correctly. The `t34` recipe shows exactly this.

`worldTransforms(parts)` chains translation + yaw down the hierarchy; `toWorld(t, p)` maps a local point. QA and the renderer read world space from there.

## LODs

| LOD | Use | What a recipe typically does |
|---|---|---|
| 0 | Hero / close | Full detail, high segment counts |
| 1 | Mid distance | Fewer segments, small parts kept |
| 2 | Far | Masses only: drop hatches, windows, rivets; 6-segment cylinders |

**LODs are re-runs, not decimation.** `compile(asset, { lod })` calls `build` again with `ctx.lod` set. The far LOD keeps named parts, pivots and silhouette because the author chose what to drop. Each LOD has its own triangle budget.

## Batching: parts → pivots

**`toGlb` merges every static part into its nearest pivot ancestor by default (`mergeToPivots`, `src/export/merge-pivots.ts`).** A pivot is anything with no mesh (a `ctx.group`, `ctx.emitter`, `ctx.socket`) or a part with `motion`. Groups, emitters and sockets always survive batching as named nodes. Batching also splits by surface: opaque geometry merges into the pivot's own mesh; each other surface in use becomes one child `<pivot>_<surface>` (e.g. `body_glass`), one draw call each. Static top-level geometry becomes one `body` node.

| Asset | Draw calls after merge |
|---|---|
| A static prop or building | 1 (`body`) |
| A shampoo bottle: opaque cap, translucent body | 2 |
| A tank | `body` + `turret` + `gun` + one per road wheel (each spins independently) |

So: **draw calls = movable pieces with geometry.** Names the engine binds to (`turret`, `gun`, `road_wheel_l_0`) survive; static detail names (`turret_hatch`) don't. QA and `real.measures` run on the unmerged compile, so they still see every part. Pass `toGlb(asset, { keepParts: true })` to keep one node per part (debugging, editors).

Planned (M3): bake motion into vertex attributes (pivot + spin axis per vertex) so a shader animates all wheels in one draw call.

## GLB layout

Validity: every exported shape is checked by the Khronos glTF-Validator in the test suite (`src/export/validator.test.ts`): 0 errors. Production rules and remaining gaps: [glb-production.md](../architecture/glb-production.md).

| glTF element | Content |
|---|---|
| `scene[0]` | One root node named after the asset, rotated Z-up/+X-front → Y-up/+Z-front |
| `nodes` | One per **pivot**, `translation` = `at`, `rotation` = yaw quaternion, plus `body` for static top-level geometry. `{ keepParts: true }` keeps one node per part |
| `meshes` | One per pivot (and surface) with geometry, static parts merged in. `POSITION`, `NORMAL`, `TEXCOORD_0` (float32); `COLOR_0` normalised u16 RGBA; indices u16 when ≤ 65,535 vertices, else u32 |
| `materials` | At most 4, one per surface in use, all over the same trim sheet: `opaque` (`ts23d_trim`), `cutout` (alpha-test, double-sided), `glass` and `translucent` (`KHR_materials_transmission` + `_volume` + `_ior`; alpha-blend fallback) |
| `animations` | Two clips: `rest` first (static, so viewers that autoplay the first clip open paused), then `run`: 4 s, every motion rounded to whole cycles (`cyclesOf`) so the loop is seamless, spins ≥ 12 keys per turn, linear, time accessors shared. `toGlb()` exports it only with `{ animations: true }` (glTF has no autoplay flag; games drive pivots from code). `t3d build` bakes it by default so viewers show play controls; `--no-animations` skips it |
| `extras` | Root: `{ kind, lod, units: 'metres', up }`. Nodes: `ts23d.emitter`, `ts23d.socket` |

Textures: the painted trim sheet, bound to every surface material (`--sheet external` by default: shared PNGs next to the GLBs). With `--sheet none` vertex colour alone carries the look.

Shipped since: the painted trim sheet (albedo, normal, ORM), embedded or as shared external PNGs, `TANGENT` only when a sheet is bound ([04](04-materials.md)).
